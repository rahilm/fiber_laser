# Translations and cutting-text fonts

## Catalogues

`mlaser/i18n/en.json` is the source of truth for every user-visible string
(format `mlaser-i18n/1`, see `mlaser/i18n/__init__.py`):

- `strings`: readable id (`area.name`) → English text. Placeholders are named, Python
  `str.format` style (`{minutes}`).
- `args`: the positional order of the placeholders.
- `legacy`: the original program's opaque keys (`mf15`, `pd125`, ...) → ids, so old call sites
  and translations imported from an original install line up.

Code looks texts up with `tr("panel.x")`, `ctx.tr.format("panel.x", n=3)` or
`tr_.bind(widget, "panel.x", setter)` (`mlaser/ui/i18n.py`). A new string gets a readable id
in `en.json` first.

Another language is `mlaser/i18n/<code>.json` with `language`, `name` and `strings` (same
ids). Lookup order at run time, per string:

1. the shipped JSON catalogue of the current language;
2. a compiled Qt Linguist file `<code>.qm`, from the user's language folder
   (`~/.mlaser/lang`, or `$MLASER_LANG_DIR`) first, then the shipped `mlaser/i18n/qm/`;
3. texts imported from the user's own Mlaser install (`python -m mlaser.i18n import`);
4. English.

The JSON is the reviewed copy that ships. A `.qm` lets a translator try work in the running
program before it is imported. The original's texts come last because they are imported by
machine, keyed by opaque ids, and use printf placeholders.

## Translator workflow (Qt Linguist)

```sh
# 1. export: every id of en.json, with existing translations carried over
python -m mlaser.i18n ts de -o de.ts                 # from mlaser/i18n/de.json if it exists
python -m mlaser.i18n ts de --merge old/de.ts -o de.ts
python -m mlaser.i18n ts de --seed-imported -o de.ts # suggest imported original texts

# 2. translate with Qt Linguist (ships with PySide6) or any TS editor
pyside6-linguist de.ts

# 3a. try it in the program: compile and drop the .qm into the language folder
python -m mlaser.i18n qm de.ts -o ~/.mlaser/lang/de.qm

# 3b. ship it: import the finished translations into the JSON catalogue
python -m mlaser.i18n ts-import de.ts --name Deutsch   # writes mlaser/i18n/de.json
python tools/i18n_check.py
```

How a catalogue entry maps to the TS file:

- `<context>` is the id's prefix (`cmd`, `panel`, ...).
- The message carries `id="<id>"`. `<source>` is the English text; `<comment>` repeats the id
  (Qt's disambiguation, so two ids with the same English text stay separate).
- `<extracomment>` lists the placeholders to keep and the original key.
- A message is `unfinished` when it is untranslated, or when its English text changed since it
  was translated (the old translation is kept for review). Only finished messages are imported
  by `ts-import` (`--unfinished` takes the rest too) and compiled by `lrelease`.
- Keep `{placeholders}` exactly as in the English text. Their order may change.
- Imported original texts (`--seed-imported`) get their `%d` / `%s` rewritten to the named
  placeholders in `args` order. They stay unfinished.

## CI check

`tools/i18n_check.py` exits 1 on:

- a key the code uses that is missing from `en.json`. This covers the original's keys
  (`tools/i18n_keys.py` scan) and readable ids passed to `tr` / `_tr` / `tr_param` /
  `<translator>.format` / `<translator>.bind`;
- a keyword passed to `<translator>.format(id, name=...)` that is not a placeholder of the id;
- in `en.json`: `args` that do not match the text's placeholders, a printf placeholder, or a
  `legacy` entry pointing to no id;
- in `<code>.json` and `*.ts` (under `mlaser/i18n/`, `translations/`, or given as arguments): an
  unknown id (JSON only), or a translation whose placeholders differ from the English.

Untranslated ids and stale `.ts` messages are warnings (`--strict` makes untranslated ids
errors). The CI architecture job runs it with `--no-legacy-scan`, and `tests/test_i18n_check.py`
runs the full check in the test job.

## Cutting-text font

Text that becomes cut geometry is drawn with the bundled **Noto Sans SC subset**
(`mlaser/cad/fontdata`, SIL OFL 1.1; Latin, Greek, Cyrillic, GB 2312). This applies to DXF TEXT
(faithful and modern import) and to Draw → Text unless the user picks another font, so the
same drawing gives the same contours on every machine:

- `mlaser.cad.text.DEFAULT_FONT` and `mlaser.cad.fonts.default_text_family()` are the bundled
  family.
- A bundled family name always resolves to the bundled file, even when a full Noto Sans SC is
  installed.
- An unknown family falls back to the bundled font, not to an installed one.
- The CFF outlines go through the same GGO_BEZIER-style record path as TrueType faces (cubic
  spline glyphs).
- A font chosen explicitly (an installed family, a font file, or a DXF style's font file) is
  still used.

The original's lookup is text-font mode `"system"`: 宋体 / SimSun (which the Wine parity harness
maps to WenQuanYi Micro Hei), then the installed fallbacks. Select it with
`MLASER_TEXT_FONT=system` or with a ParityProfile option:

```python
ORIGINAL.derive("original-system-fonts", "...", options={"text_font": "system"})
```

Use it when comparing text with the original. The goldens' text-font probe
(`tools/make_goldens.py`, `manifest.json`) is now the bundled font, the same on every host.
The 23 TEXT cases were regenerated once for this change; in `"system"` mode the probe is the old
WenQuanYi one.

Report printing (`mlaser/report/printing.py`, `FONT = "SimSun"`) is a Qt UI font with Qt's
fallback, not cut geometry, and is unchanged.
